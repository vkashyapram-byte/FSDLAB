  </style>
</head>
<body>
  <div class="form-box">
    <h2>User Registration</h2>
    <form id="regForm" onsubmit="return validateForm(event)">
      <div class="form-group">
        <label for="name">Full Name</label>
        <input type="text" id="name" placeholder="Enter full name">
        <span class="error" id="nameError"></span>
      </div>

      <div class="form-group">
        <label for="email">Email Address</label>
        <input type="text" id="email" placeholder="example@domain.com">
        <span class="error" id="emailError"></span>
      </div>

      <div class="form-group">
        <label for="password">Password</label>
        <input type="password" id="password" placeholder="At least 8 characters">
        <span class="error" id="passwordError"></span>
      </div>

      <div class="form-group">
        <label for="confirmPassword">Confirm Password</label>
        <input type="password" id="confirmPassword" placeholder="Re-enter password">
        <span class="error" id="confirmPasswordError"></span>
      </div>

      <div class="form-group">
        <label for="phone">Phone Number</label>
        <input type="text" id="phone" placeholder="10-digit mobile number">
        <span class="error" id="phoneError"></span>
      </div>

      <button type="submit">Register</button>
      <div class="success" id="successMsg"></div>
    </form>
  </div>

  <script>
    function showError(elementId, message) {
      document.getElementById(elementId).innerText = message;
    }

    function clearErrors() {
      const errorSpans = document.querySelectorAll('.error');
      errorSpans.forEach(span => span.innerText = '');
      document.getElementById('successMsg').innerText = '';
    }

    function validateForm(e) {
      e.preventDefault();
      clearErrors();
      let isValid = true;

      const name = document.getElementById('name');
      const email = document.getElementById('email');
      const password = document.getElementById('password');
      const confirmPassword = document.getElementById('confirmPassword');
      const phone = document.getElementById('phone');

      // 1. Name validation (min 3 chars)
      if (name.value.trim().length < 3) {
        showError('nameError', 'Name must be at least 3 characters.');
        isValid = false;
      }

      // 2. Email regex validation
      const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
      if (!emailRegex.test(email.value)) {
        showError('emailError', 'Enter a valid email address.');
        isValid = false;
      }

      // 3. Password min length 8
      if (password.value.length < 8) {
        showError('passwordError', 'Password must be at least 8 characters.');
        isValid = false;
      }

      // 4. Confirm password match
      if (password.value !== confirmPassword.value) {
        showError('confirmPasswordError', 'Passwords do not match.');
        isValid = false;
      }

      // 5. Phone number 10 digits
      const phoneRegex = /^\d{10}$/;
      if (!phoneRegex.test(phone.value)) {
        showError('phoneError', 'Enter a valid 10-digit phone number.');
        isValid = false;
      }

      if (isValid) {
        document.getElementById('successMsg').innerText = 'Registration Successful! All validations passed.';
      }
      return false;
    }
  </script>
</body>
</html>

💬 Viva Questions & Answers

1. What is form validation and why is it important?

Form validation is the process of verifying that user input submitted through a web form conforms to specified criteria and business rules (e.g., non-empty fields, valid email syntax, minimum password length) before processing or sending to a server. It ensures data accuracy, integrity, and security, and improves user experience by giving immediate feedback.

2. What is the difference between client-side and server-side validation?

Client-side validation runs in the browser using HTML5/JavaScript before sending data to the server. It gives immediate feedback without network latency. Server-side validation executes on the backend server. It is essential for security because client-side validation can be disabled or bypassed by malicious actors.

3. What is a regular expression and how is it used in JavaScript?

A regular expression (RegEx) is a sequence of characters that forms a search pattern used for text search and string validation. In JavaScript, regex objects can be created using literals (/.../) or the RegExp constructor, and evaluated using methods like .test(string) (returns boolean) and .match(regex).

4. What is the preventDefault method used for?

The event.preventDefault() method prevents the default browser action from taking place. On form submit events, it stops the page from reloading or navigating away, allowing custom JavaScript validation and asynchronous handling.

5. How can you check if an input field is empty using JavaScript?

You can read the input's value property, remove surrounding whitespace using .trim(), and compare against an empty string or length 0: if (inputElement.value.trim() === '') { /* is empty */ }

6. What are HTML5 built-in validation attributes?

HTML5 provides declarative validation attributes including: required (must not be empty), minlength and maxlength, min and max, pattern (specifies regex), and specific input types such as type="email", type="number", and type="url".

7. Why should client-side validation not replace server-side validation?

Client-side validation can easily be bypassed by disabling JavaScript in the browser, editing the DOM via DevTools, or making direct HTTP requests via Postman or curl. Hence, client-side validation is strictly for user experience, while server-side validation is mandatory for application security.

💬 Viva Questions & Answers

1. What is React and why is it used?

React is an open-source JavaScript library developed by Meta for building dynamic and interactive user interfaces, especially single-page applications (SPAs). It is used for its component-based architecture, efficient Virtual DOM rendering, unidirectional data flow, and rich ecosystem.

2. What is JSX in React?

JSX stands for JavaScript XML. It is a syntax extension for JavaScript that allows developers to write HTML-like markup directly within JavaScript code. Babel or modern bundlers compile JSX down into standard React.createElement() function calls.

3. What are props in React?

Props (short for properties) are read-only inputs passed from a parent component down to a child component. They allow components to be dynamic and reusable by parameterizing data. In React, props are immutable within the child component.

4. What is the difference between a class component and a functional component?

Class components are ES6 classes extending React.Component with a render() method and lifecycle methods (e.g. componentDidMount). Functional components are plain JavaScript functions that take props as an argument and return JSX. With the introduction of React Hooks (like useState, useEffect), functional components are the modern industry standard.

5. What is the purpose of the npm run dev command?

npm run dev starts the Vite local development server with Hot Module Replacement (HMR). It serves the application locally (typically at http://localhost:5173) and updates changed modules instantly in the browser without losing component state.

6. What is the Virtual DOM in React?

The Virtual DOM is a lightweight in-memory JavaScript representation of the real DOM. When component state or props change, React updates the Virtual DOM, performs reconciliation (diffing algorithm) to compute minimum required changes, and batch-updates the real DOM efficiently.

7. Why is a component-based architecture beneficial in frontend development?

It promotes reusability, modularity, readability, and maintainability. Components isolate their markup, style, and logic, making complex user interfaces easier to test, debug, collaborate on, and scale.

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <h2>Counter: {count}</h2>
      <button onClick={() => setCount(count + 1)}>Increment</button>
      <button onClick={() => setCount(count - 1)}>Decrement</button>
      <button onClick={() => setCount(0)}>Reset</button>
    </div>
  );
}

export default Counter;

  3. Step 3: Create a new file named TodoList.jsx inside the src folder:

    src/TodoList.jsx 
    import { useState } from 'react';

function TodoList() {
  const [todos, setTodos] = useState([]);
  const [input, setInput] = useState('');

  const addTodo = () => {
    if (input.trim()) {
      setTodos([...todos, input]);
      setInput('');
    }
  };

  const removeTodo = (index) => {
    setTodos(todos.filter((_, i) => i !== index));
  };

  return (
    <div>
      <h2>To-Do List</h2>
      <input 
        value={input} 
        onChange={(e) => setInput(e.target.value)} 
        placeholder="Add task" 
      />
      <button onClick={addTodo}>Add</button>
      <ul>
        {todos.map((todo, i) => (
          <li key={i}>
            {todo} <button onClick={() => removeTodo(i)}>Remove</button>
          </li>
        ))}
      </ul>
    </div>
  );
}

export default TodoList;

💬 Viva Questions & Answers

1. What is state in React?

State is an internal data storage mechanism managed within a component. Unlike props (which are passed down from above and read-only), state is mutable by the component itself using its setter function. When state updates, React schedules a re-render of that component.

2. What is the useState hook and how is it used?

useState is a built-in React hook that allows functional components to declare local state variables. It takes the initial state value as an argument and returns a 2-element array containing the current state value and a state updater function: const [state, setState] = useState(initialValue);

3. How is state different from props?

Props are external arguments passed down from a parent component; they are read-only and immutable by the recipient. State is private and fully controlled inside the component itself. Props allow configuration; state holds data that changes over time based on user interactions.

4. What happens to the UI when state changes in React?

When the setter function returned by useState is called with a new value, React detects the change, enqueues a re-render for that component and its children, recalculates the Virtual DOM diff, and efficiently paints the changed DOM nodes to the browser.

5. What is an event handler in React?

An event handler is a function passed as a prop to JSX elements (e.g. onClick, onChange, onSubmit) to execute logic in response to user actions like clicking, typing, or submitting forms. React wraps native browser events in cross-browser SyntheticEvent objects.

6. What is the spread operator and how is it used with arrays in React?

The ES6 spread operator (...) expands elements of an existing array into a new array. In React state updates, it is used to maintain immutability: setTodos([...todos, newTodo]) creates a new array reference containing all previous items plus the new item, ensuring React recognizes the state mutation.

7. Why should state not be mutated directly in React?

Directly mutating state (e.g., todos.push(item) or count++) does not trigger a re-render because React performs shallow reference equality checks on state. Without calling the setter function, React is unaware that data has changed, leading to silent synchronization bugs and stale UI.
